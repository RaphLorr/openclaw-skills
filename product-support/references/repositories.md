# OpenClaw 本群仓库访问

- 优先使用当前消息中由 plugin 正式注入的本群“项目上下文”，其中包含仓库用途、类型、绑定分支和本地目录。
  选择与咨询功能相符的 `kind="code"` 仓库；`knowledge` 文档仅作为辅助，不替代代码关联门槛。
- 上下文有多个仓库时，按产品端和描述定位；仍有歧义只问功能属于哪个端，不随便选一个。
  克隆中、克隆失败、本地目录不可读时不能解释代码行为。
- 必要且有权限时可调用 `wechat_project(action="status", group=当前群ID)` 核对仓库状态。
  当前 OpenClaw 工具的仓库管理查询可能只允许管理员；普通群成员已有可信注入上下文时，
  可直接只读对应本地副本，不为此申请管理员授权。若查询被拒且无可核实上下文，说明无法核实，不绕过工具去遍历注册表。
- 不把 `wechat_project(action="project")` 当作 OpenClaw 已有动作；它是 Hermes 的 TAPD 查询用法。
  当前 OpenClaw TAPD 归属由 `tapd` skill 解析，与代码库关联是两个独立条件。
- 仅读取本群已绑定的本地目录，使用 `rg` 定位、读取相关文件，必要时只读查看 git 分支和提交。
  不在持续同步目录里 checkout、编辑文件或安装/运行项目，不使用裸 `git pull/fetch/ls-remote`。
- 需要核对其他分支时，仅对本群已绑定仓库使用工具实际提供的 `inspect_branch`，
  等待 ready 后读取返回的独立目录；完成后 `release_inspection`，不得用 link 临时换群绑定。
  工具不可用时报告证据缺口，不自行 clone、改绑定或引入另一个项目。
- 内部证据可以记录具体文件和版本；客服回复不暴露这些技术细节。
